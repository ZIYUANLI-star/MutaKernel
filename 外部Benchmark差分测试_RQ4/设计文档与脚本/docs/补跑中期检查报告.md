#### 13 个 skip 的根因分析

**全部** 13 个 skip 都是 `self_ref` 类型（无 PyTorch 参考实现），`pytorch_ref` 类型 **0 个 skip**。

| 问题类型 | 数量 | 示例 | 说明 |
|---------|------|------|------|
| forward() 参数不全 | 13 | `problem_32` (dropout): `forward(self, x)` 只传 1 个参数，但底层 Triton kernel 需要 `(x, x_keep, p)` 3 个 | self_ref wrapper 封装时遗漏了额外参数 |

**根因**：师兄在生成 `self_ref` 类型的 wrapper 时，`Model.forward()` 只暴露了主输入 tensor，遗漏了辅助参数（如 dropout 的 mask 和概率、attention 的 kv 等）。`get_inputs()` 只返回部分参数，导致底层 Triton kernel 调用时缺参数报错。

**影响**：
- 13/116 self_ref kernels 受影响（11%）
- 0/26 pytorch_ref kernels 受影响
- skip 率：self_ref 18.8% vs pytorch_ref 0%

## 五、结论与建议

### 数据质量评估

1. **AI CUDA Engineer：适配质量 A**——签名问题 100% 修复，3 个 skip 均为 LLM 生成的 CUDA 代码本身编译失败，不可避免
2. **TritonBench-G：适配质量 B+**——核心问题修复，但 13 个 `self_ref` kernel 仍有 forward() 参数封装遗漏

### 对师兄的建议

1. **TritonBench-G 13 个 self_ref 的 fix**：需要修改这些 problem 文件的 `forward()` 和 `get_inputs()`，把 Triton kernel 实际需要的所有参数都传入。涉及的 kernel：
   - `problem_9` (rope_embedding)
   - `problem_18` (bgmv_shrink_kernel)
   - `problem_25` (flash_attn)
   - `problem_32` (dropout_triton)
   - `problem_36` (attention_score)
   - `problem_37` (batched_vecmat_mult)
   - `problem_43` (kldiv_ops)
   - `problem_51` (max_reduction)
   - `problem_64` (bgmv_expand_slice)
   - `problem_69` (mixed_sparse_attention)
   - `problem_77` (seeded_dropout)
   - `problem_84` (attention_kernel)
   - `problem_88` (matmul_dequantize)

2. **registry.json 路径分隔符**：师兄电脑是 Windows，生成的 registry 用了反斜杠 `\`，已在本次实验中手动修复为 `/`。建议在生成脚本中加 `.replace('\\', '/')` 或用 `pathlib.PurePosixPath`

3. **当前实验可继续运行**——13 个 skip 不影响其余 129 个 tritonbench kernel 的测试
