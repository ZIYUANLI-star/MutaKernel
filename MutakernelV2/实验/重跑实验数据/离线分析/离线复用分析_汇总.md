## 1. 全局保守假设（适用于所有分析器）

1. **首杀即停（early exit）**：每条观测的 trials 在第一次 sound divergence 处截断，
   因此每个见证探针只有 **1 条**已记录见证用例。由此：
   - "闭合"只能判"已记录见证用例是否落入 held-out top-k 计划" → 闭合率是**下界**
     （计划内未执行的用例也可能杀死该探针）；
   - "≥2 维度交叉确认率"是**下界**（恒为 0，直到有多见证证据）；
     "sole-detector 数"相应是**上界**。
2. **random 轮折叠为 iid 用例**：与 `run_e1_probe_study --phase map` 口径一致
   （map 匹配用 `policy or "iid"`；A13 预算记账则保留 "random" 独立标签）。
3. **map 训练集含 baseline iid 杀**（沿用现有 map 阶段约定），但闭合率评估分母
   只算盲区见证（74），不算 baseline 已杀。
4. **CSE lane1/2 为 VRAM-safe 快内核**，其成本统计对终版有低偏（重内核在
   lane0/3/4/5）；终版重算后 CSE 成本预计上移。

## 2. 分析器 1 — §5.6 交叉拟合闭合率（蓝图行 797–815 的 "closes ? %"）

任务级 5 折交叉拟合（复用 `src/audit/crossfit.assign_folds` 的内容寻址折分配，
seed=`e1-crossfit-v1`），k=8 计划用例。

| 蓝图格子 | interim 值 |
|---|---|
| "the map closes **? %** of witnessed blind spots within the first k=8 planned cases"（交叉拟合，正文） | **73.0 %（54/74，离线保守下界）** |
| 非交叉拟合上界（附录 curve） | **100 %（74/74）@k=8**（k=5 即达 100%） |
| 折数 "? folds" | 5（参数化，可改） |

按折汇总：fold0 17/27，fold1 5/7，fold2 13/14，fold3 15/20，fold4 4/6。

闭合曲线（`a1_closure_curve.csv/png`）：下界 k=1: 10.8% → k=2: 35.1% → k=3 起饱和于
73.0%；上界 k=1: 14.9% → k=3: 90.5% → k=5: 100%。下界在 k=3 饱和的结构原因：
未闭合探针的见证用例在其训练折 map 中**任意名次都不出现**（该用例在同故障类的
其他任务上没有杀过任何探针），属于"跨任务不可迁移的见证"。

**下界与上界的差距 = 20 个探针（27 pp），其中：**

- **6 个 `unclosed_evidence_insufficient`（小规模验证重跑候选清单，见
  `a1_unclosed_witnessed.csv`）**——top-8 计划中有 1–2 个用例从未在该探针上执行过
  （首杀截断所致），重跑这些计划用例有机会闭合：
  `L1_P16__launch_config_mutate__0`、`L1_P35__epsilon_modify__1`、
  `L1_P49__init_modify__1`、`L1_P98__const_perturb__10`、
  `L1_P98__const_perturb__11`、`L1_P99__const_perturb__4`。
  重跑代价极小：≤ 6 探针 × ≤ 2 个用例 × 单轮中位 0.34 s（+ 每探针一次 JIT），
  单卡 < 30 分钟。**重跑全部命中时下界至多升到 81.1%（60/74）。**
- **14 个 `unclosed_all_planned_conclusive`**——top-8 计划用例在该探针上全部执行且
  全部 conclusive 未杀：在 interim map 下重跑同样计划**不会**闭合它们，属于交叉拟合
  意义下的真实未闭合（终版数据重排 map 名次后可能变化）。

## 4. 分析器 3 — budget–recall 曲线 + A13 双口径（§5.7 saturation / A13 反驳）

**budget–recall**（`a3_budget_recall_curve.csv/png`；分母 = 74 已记录见证）：

| 累计召回 | 所需单探针轮预算（combined 口径） |
|---:|---:|
| 50 % | 23 轮 |
| 80 % | 24 轮 |
| 90 % | 27 轮 |
| 95 % | 29 轮 |
| 100 % | 76 轮（唯一 CSE 见证：32 equiv + 44 CSE） |

结构解读：equiv 搜索前 20 轮是随机轮，仅贡献 6 个见证；进入定向轮（第 21 轮起）后
3 轮内即从 8% 跳到 78%。**§5.7 "saturates at ? invocations" 的 interim 初值 ≈ 29 轮
（95%）/ 32 轮（equiv 预算内即覆盖除 CSE 见证外全部）**；同时该曲线本身是"定向轮前置可大幅省预算"的
直接证据（供部署预算建议）。

**A13 双口径**（`a3_policy_yield.csv/png`）：

| 组 | 轮数 | 见证 | 逐轮命中率 | 预算占比（轮） |
|---|---:|---:|---:|---:|
| equiv 随机轮 | 10,410 | 6 | 0.058 % | 65.3 % |
| equiv 定向轮 | 5,524 | 67 | 1.213 % | 34.7 % |
| CSE 随机轮 | 9,880 | 0 | 0 | 38.9 % |
| CSE 定向轮 | 15,502 | 1 | 0.0065 % | 61.1 % |

**定向轮逐轮命中率是随机轮的 21.1 倍**（equiv 阶段），且随机轮占预算大头（65%）
却只贡献 8% 见证——正面回应 A13 "分母混淆"攻击：定向策略的优势在消除轮次配比
混淆后依然成立。逐策略明细（top：denormals 9.1%、head_heavy 7.6%、near_epsilon
6.7%、extreme_magnitude 5.0%/轮）在 CSV 中，含按轮数与按 GPU 墙钟时间两种预算占比。

**CSE 收官后重算终版（远程，CPU-only，只读运行目录，写 analysis/final）：**

```bash
MK_PROJECT_ROOT=/root/mk_v2 /root/miniconda3/bin/python \
  /root/mk_v2_runs/e1/analysis/scripts/offline_reuse_all.py \
  --e1-dir /root/mk_v2_runs/e1 \
  --out-dir /root/mk_v2_runs/e1/analysis/final \
  --cse-obs "/root/mk_v2_runs/e1/cse_observations_lane*.jsonl" --final
```

（`--cse-obs` 支持 glob；终版会自动按 probe_id 去重取最新记录，容纳 lane 重组/
requeue 的历史重复。本地重算同一命令换 `--e1-dir data/e1 --out-dir outputs` 即可。）
