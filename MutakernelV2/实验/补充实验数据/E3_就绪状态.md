## 关键设计（与 M-full/M-dir 同口径）

- 所有 port 计划以 `TestCaseSpec` 表达，`candidate_run_cost` 合计**恰好 32**（`assert_budget_matched` 在计划期强制；`BudgetState` 在执行期每次候选启动前扣费，超支即拒）。B7 的 repeat-pair 按上游冻结口径每 trial 计 2 次调用。
- 判定统一走 `src.validation` 管线；B9 例外地按上游协议使用 fp64 CPU 参考 + 逐 (subject,dtype) 校准绝对容差（validator.rs 语义逐条移植）。
- 数据分离：`run` 子命令默认拒绝非 CPU 设备（需 `--allow-gpu`）；所有冒烟只用 C1/KernelBench 任务（候选=参考实现本身），C2–C5 候选零执行。

## 验证记录

- 远程全量测试：`cd /root/mk_v2 && CUDA_VISIBLE_DEVICES= python -m pytest tests -x -q` → **172 passed**（其中新增 41 个：`test_e3_ports.py` 20、`test_b11_sanitizer.py` 9、`test_e2_inclusion.py` 12）。
- B1u 冒烟（KB_L1_P1，CPU）：5 案例 / 5 次调用，全 PASS。
- B9 校准闭环（KB_L1_P1 matmul，CPU）：未校准 fallback 容差 1e-5 下 32/32 FAIL（fp32 2048³ 归约误差 ~5e-3，**协议预期行为**，正是上游要求先校准的原因）→ 控制误差 p95×1.5 = 9.89e-3 → 校准后 32/32 PASS。结论：对归约类科目，B9 执行前必须先跑控制校准，`calibrated_tol` 参数通道已就绪。
- compute-sanitizer：`/usr/local/cuda/bin/compute-sanitizer`，版本 **2023.1.1**（CUDA 12.1 toolkit），`find_sanitizer()` 的 fallback 路径命中。蓝图 §5.1.3 环境行可回填。
