## 0. 设计总纲：一个 4.5/5 的 Evaluation 章节长什么样

FSE 审稿人给 Evaluation 打高分的五个隐含判据，本设计逐条对齐：

| 判据 | 本设计的对应机制 |
|------|-----------------|
| ① 主张与证据严格对齐，无过度声明 | 每个 RQ 只由指定实验回答；"缺陷"一词只用于**独立双盲审计确认**的告警；`NO_DEFECT_FOUND ≠ 正确` 贯穿全部表格措辞 |
| ② 基线公平且强 | 三视图对比（native 原生协议 / 等调用预算 / 等 GPU 时间），任何方法不因"多跑了测试"得分；纳入 2026 年最新验证器（KernelBenchX、Correctness-Illusion 口径、robust-kbench）与形式化路线（Kuiper、ProofWright）的定位对比 |
| ③ ground truth 不循环 | 双保险：(a) 检测器结果封存后生成双盲人工审计队列；(b) **外部已标注语料**（gpuemu 26-op corpus、Kuiper 已证明 L1 kernel）提供不依赖我们自己标注的召回/误报测量（E3） |
| ④ 统计成熟 | 任务聚类 bootstrap CI、配对 exact McNemar + Holm 校正、INCONCLUSIVE 双极端敏感性、效应量报告；主指标与排除规则先于全量运行冻结 |
| ⑤ 可复现 artifact | 每个非 PASS 观测一个可复放证据包；冻结 manifest 链；匿名 artifact + smoke 模式 |

主叙事的证据链（Diagnosis-to-Validation）与实验的对应：

```
E4 受控盲区测量（诊断）──► E5 映射受控验证（机制）──► E2/E3 部署对比（产品）
        │                                                    │
        └──── E1 自然误接受（问题存在性）◄───────────────────┘
E0 执行基座可信性（一切之前）      E6 开销      E7 闭环案例      E8 泛化
```

### 1.1.1 B3–B6 的性质说明：审稿人点名的"简单强基线"消融阶梯

B3–B6 不是文献中已发表的验证器，而是**本文按 Reviewer A 的点名清单构造的
简单增强基线**（评审原文："stronger but still simple baselines, such as more
random seeds, diversified input distributions, boundary-value tests,
dtype/mode/configuration stress tests, or LLM self-review"——B3↔more seeds、
B4↔diversified distributions、B5↔boundary-value tests、B6↔dtype/mode/config
stress、B10↔LLM self-review，一一对应）。全部 case 组成已在
`configs/fse_strategy_matrix.json` 预注册冻结，每行恰 32 次 candidate 调用。

它们与两个 MutaKernel 行构成严格递进的消融阶梯，相邻两级差值各回答一个问题：

```
B1(5 次随机) → B3(32 次随机)      差值 = 测试数量的贡献
             → B4(值分布多样化)    差值 = 分布多样性的贡献
             → B5/B6(边界/上下文)  差值 = 经典 BVA 与执行上下文轴的贡献
             → MutaKernel-full     差值 = 五维联合 + 故障类知识策略库的贡献
             → site-directed       差值 = 按候选位点定向选题的贡献
```

没有这个阶梯，E2 只能得出"MutaKernel 强于 KernelBench"的粗结论（可被
"你多跑了 6 倍测试"一句击穿）；有了阶梯，改进的每一层来源被分别隔离量化。
注意 B4/B5 复用 MutaKernel 策略库中的单条策略作为构件，但**均匀分配、
不使用故障类先验与维度组合**——被隔离的变量恰是"定向性"本身。

### 1.3 明确排除项及理由（防审稿人问"为什么没有 X"）

- **FastKernels**（Snowflake, arXiv:2605.23215, 2026）：定位是生产级性能对齐基准，正确性组件依赖其推理框架栈，与单 kernel 验证器不可比；在 Related Work 定位，其"沙箱高分≠生产正确"的发现作为我们动机的独立佐证。
- **SOL-ExecBench / ComputeEval**：以性能上界/综合能力为主，正确性协议与 B1 同族；若 ComputeEval 的 CUPTI 功能检查在冻结日前可复现，作为附录行，否则 Related Work。
- **MUTGPU / CLTestCheck / MutateNN**：变异测试方法学同行，是我们 meta-evaluation 的谱系而非验证器基线，进 Related Work。

## 3. 实验设计（E0–E7）

### E0 执行基座可信性与历史翻转率（一切结果的前提）

**动机**：我们发现并修复了 V1 执行基座的三个 soundness 缺陷（初始化 RNG 不同步、
按形状顺序拷贝权重、输入共享）。审稿人有权问："修复对结论影响多大？"——
这个问题本身就是一个有发表价值的观测（harness 缺陷如何污染测量结论）。

**设计**：
1. 分层抽样（L1/L2 × 16 算子 × killed/survived，n≈300 探针），用修正基座重跑
   Phase I 基线判定；
2. 报告**判定翻转率**：flip(killed→survived)、flip(survived→killed)，按
   level 与"参考模型是否含随机初始化参数"分层；
3. 预期与假设：L2（大量随机参数任务）翻转率显著高于 L1；该差异直接验证
   状态污染假设（历史旁证：L2 杀死率 89.7% vs L1 49.6%）。

**产出**：Table "Harness-soundness flip rates"；决定 E4 全量重跑的成本预估。
**回应**：Reviewer A/B 的"启发式管线可信性"+ 方法学透明度加分项。

### E1（RQ1）自然误接受下界：真实被接受 kernel 里有多少确认缺陷

**设计**：
1. D2 队列 stable-ID 对账并冻结（population/applicability 计划：保留
   unsupported/missing/partial/inconclusive 分层）；
2. 全部可执行验证器行（§1.1）在冻结队列上运行（与 E2 共享执行）；
3. **封存后**生成人工审计队列：所有验证器**告警并集** + 执行未决 subject +
   全 PASS 层的预注册分层阴性抽样（按数据集×语言×任务级分层，每层 n≥10）；
4. 双盲双标注（政策中立证据包：物化输入 + 自包含复放脚本，不暴露
   策略/seed/检测器身份）→ 仲裁 → kappa/混淆矩阵；
5. 主结果：**确认契约内缺陷的下界**（按数据集/语言/任务级/故障类分解，
   带抽样权重的区间估计）；contract 外发现（extended-contract）单列。

**预期表格**：
- Table 1: 各数据集的确认误接受下界（分数 + 聚类 bootstrap 95% CI）；
- Table 2: 确认缺陷的故障类分布（与 D7 的自然错误分布对照）；
- Figure: 告警 → 确认的漏斗图（含 INCONCLUSIVE 全量可见）。

**与 V1 的关键差别**：V1 的 "222 defective" 变为 "N stress-flagged，其中
M 独立确认"；60.23% 这类数字全部换成带审计确认与 CI 的口径。
**回应**：Reviewer A 第 1 条（直接审计真实 kernel，我们做了）+ B 的 Q1（误报率）。

### E2（RQ2）预算匹配的验证器对比：定向性是否优于"更多测试"

**设计**（预注册矩阵已冻结 `configs/fse_strategy_matrix.json`，本实验扩充外部行）：

| 行 | 预算 | 备注 |
|----|------|------|
| B1 five-IID 锚点 | 5 | 描述性，不进等预算比较 |
| B3 IID-32 | 32 | 等预算随机对照 |
| B4 多样化值分布 | 32 | |
| B5 边界值套件 | 32 | |
| B6 dtype/mode/config 网格 | 32 | |
| MutaKernel-full（无先验全套件） | 32 | 方案 (a)，消融对照 |
| **MutaKernel-site-directed（位点定向）** | 32 | 方案 (c)：静态指纹 → FaultToStressMap 查表选题（70/30；另附 50/50、90/10 敏感性行） |
| B7 robust-kbench | native 不限 + port 32 | 双轨 |
| B8 KernelBenchX | native（其任务域）+ port 32 | 双轨 |
| B9 seeded-fuzz + fp64 ref | port 32 | 三要素移植 |
| B10 LLM self-review | 单独计费 | token 成本换算 GPU 秒当量 |
| B11 Compute Sanitizer | 单独计程 | 告警类型单列（内存/竞态） |
| MutaKernel unrestricted | 不限 | 第三视图（native 协议），连接 E4/历史 pilot |

三视图强制报告：native 不限 / 等 32 调用 / 等 GPU 时间（预注册 wall budget）。

**指标**（全部以 E1 的确认标签计算）：
- 确认缺陷召回（该行告警∩确认缺陷 / 确认缺陷并集）；
- 审计告警精度；
- time-to-first-counterexample（中位数 + p95）；
- GPU 秒/确认缺陷；检出-成本 Pareto 前沿图。

**统计**：同一 subject 两验证器 → 配对 exact McNemar；行族 Holm 校正；
任务聚类 bootstrap CI（10k）；效应量（odds ratio）。

**关键假设的可证伪表述**（预注册）：
- H2a: site-directed ≥ full ≥ IID-32（等预算召回）；若 site-directed ≤ full，
  则"变异指导无逐候选增益"照实报告，定向性主张降级为套件级；
- H2b: MutaKernel-full 召回 ≥ robust-kbench-port 且 ≥ B9-port（等预算）；
  若 B9 的 fp64 参考 + 校准容差在某故障类上占优，做**组合行**
  （MutaKernel 策略 + fp64 参考）的追加消融——两条正交设计轴的组合
  本身就是有价值的发现。

**预期表格/图**：主对比大表（三视图 × 全行 × 4 指标 + CI）、Pareto 图、
per-fault-class 召回热力图、McNemar 显著性矩阵。
**回应**：Reviewer A 第 4/5 条、B 的 Q5，全文最重的一张表。

### E3（RQ2 外部效度）已知答案对测：在别人的 ground truth 上互测

**动机**：E1/E2 的标签来自我们组织的审计，审稿人可质疑标注偏倚。
E3 用**两个外部公开标签源**闭环：

**E3a — gpuemu 语料（D3）**：16 正确对照 + 10 已知 bug 变体，全部可执行
验证器行跑一遍，直接报告 recall / FPR（无需任何我们的标注）。
特别报告：MutaKernel 位点指纹在这 10 个已知 bug 上的故障类命中率
（转录错误如缺 0.5×GELU、softmax 尾掩码 other=0 等是否落在我们分类学内——
不落在的如实计入 `not_represented`，联动 RQ3）。

**E3b — Kuiper 已验证 L1 集（D4）**：100 个带功能正确性证明的 kernel 作为
高置信正确对照，测各验证器**误报率上界**；同时与 "Next Frontier" 论文
审计出的 KernelBench 假阳/假阴样本交叉核对（他们的发现 vs 我们的发现，
一致/不一致逐例列表）。

**预期表格**：外部语料上的 recall/FPR 对比表（这是全文最"硬"的一张表，
因为 ground truth 完全不经我们之手）。
**回应**：Reviewer B 对标注主观性的根本性质疑；同时把 2026 年两个最新
相关工作（gpuemu、Kuiper）从"竞品威胁"转化为"互证资源"。
