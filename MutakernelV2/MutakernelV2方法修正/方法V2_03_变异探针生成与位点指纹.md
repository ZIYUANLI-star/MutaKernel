## 一、问题背景

V1 已经建立了首个面向 ML 数值语义 + GPU 并行语义 + LLM 错误模式的
16 算子分类学（A 算术 3 / B 并行 4 / C 数值 7 / D LLM 2），其位点搜索
（Python AST + CUDA 感知正则双路径）与变异施加逻辑经过一轮完整实验检验，
V2 全部继承。V1 的问题不在算子本身，而在**语义定位**与**用途单一**：

1. 变异体在论文叙事中滑向了"待验收对象"（审稿人 A 的混淆批评）；
2. 位点搜索能力只用于离线生成变异体，没有被用于在线验证——而它恰好是
   "候选内核里可能藏哪类错"的零成本静态证据。

## 二、本模块拟解决的问题

1. **重新定义变异体语义**：变异体 = 故障探针（fault probe），
   一个探针编码一个假设"候选内核可能在位点 s 犯故障类 F 的错"；
   探针的存活度量的是**测试套件对该假设的盲区**，不是探针自身的好坏；
2. **新增位点指纹**：把 16 算子的 `find_sites()` 从"变异前置步骤"提升为
   独立的静态分析服务，在线为任意候选内核输出故障类位点画像
   （毫秒级、零编译、零执行），供 Mode B 定向选择策略。

## 三、方法设计

### 3.1 算子分类学与故障类映射（V2 固化为机器可读表）

| 算子 | 类别 | 故障类 ID | 探针假设（"候选可能……"） |
|------|------|----------|--------------------------|
| arith_replace | A | F-ARITH | 写错算术运算符 |
| relop_replace | A | F-RELOP | 写错关系运算符 |
| const_perturb | A | F-CONST | 常量偏差 ±1 / ±1% |
| index_replace | B | F-IDX | 线程/块索引维度混淆 |
| sync_remove | B | F-SYNC | 遗漏同步屏障 |
| mask_boundary | B | F-BOUND | mask/边界 off-by-one |
| launch_config_mutate | B | F-LAUNCH | grid 少算一个 block |
| stab_remove | C | F-STAB | 遗漏 max-subtraction 稳定化 |
| epsilon_modify | C | F-EPS | epsilon 遗漏/写错 |
| scale_modify | C | F-SCALE | 遗漏 1/√d 缩放 |
| init_modify | C | F-INIT | 归约初始值写错 |
| acc_downgrade | C | F-PREC-ACC | 累加器精度降级 |
| cast_remove | C | F-CAST | 遗漏显式类型转换 |
| reduction_reorder | C | F-RED-ORD | 归约顺序敏感性 |
| broadcast_unsafe | D | F-BCAST | 遗漏显式广播 |
| layout_assume | D | F-LAYOUT | 假设输入连续 |

`operator → fault_class` 为 1:1，该表随代码发布并写入 FaultToStressMap
的 `operator_to_fault_class` 字段（V2-00 §3.8）。

### 3.2 探针生成（离线，Mode A 专用）

流程继承 V1（`generate_mutants = find_sites → apply → Mutant`），V2 变更：

1. **一阶探针 + 降采样**：每 (kernel, operator) 均匀降采样至 ≤3 个探针
   （控制 JIT 成本），降采样种子进 run manifest；
2. **探针记录 schema 扩展**：

```json
{
  "probe_id": "{kernel_id}__{operator}__{site_index}",
  "operator": "epsilon_modify", "category": "C", "fault_class": "F-EPS",
  "site": {"line_start": …, "line_end": …, "col_start": …, "col_end": …,
            "node_type": "eps_sci", "original_fragment": "1e-5f"},
  "original_sha256": "…", "mutated_sha256": "…",
  "operator_version": "…", "generation_seed": …
}
```

3. **先验等价标记保留**（V1 已实现的 `reduction_tail`、`cast:redundant`
   等 node_type 标记）：这些标记进入 EMD Layer 1 的证据，而非直接定案；
4. **禁止语义**：探针记录中不出现 killed/survived 之外的"好坏"语义字段；
   一切等价/缺陷判断在 M5/M7 完成。

### 3.3 位点指纹（新增，Mode B 核心输入）

```
function BuildSiteFingerprint(candidate_source) -> SiteFingerprint:
    tree ← try ast.parse(candidate_source)      # 失败不致命，CUDA 路径仍可用
    sites ← {}
    for op in get_all_operators():              # 16 个，全部只调 find_sites
        s ← op.find_sites(candidate_source, tree)
        sites[op.name] ← {count: len(s),
                           node_types: sorted(unique(x.node_type for x in s))}
    present ← [fault_class(op) for op in sites if sites[op].count > 0
                and not all_sites_prior_equivalent(sites[op])]
    return SiteFingerprint(subject_id, fingerprint_version, sites, present)
```

设计要点：

- **零执行**：只做正则/AST 扫描，单 kernel 典型耗时 < 50ms，可放进
  ADRS 循环的每候选路径；
- **先验等价位点剔除**：node_type 带 `reduction_tail`/`redundant` 等
  先验等价标记的位点不计入 `fault_classes_present`（它们不构成风险信号）；
- **版本绑定**：`fingerprint_version` = 算子代码版本 hash；算子改动即
  指纹版本升级，保证指纹 ↔ FaultToStressMap 的键一致性；
- **保守解释**：`count = 0` 不证明该故障类不可能（LLM 可以写出算子模式
  之外的等价错误），只表示"没有已知模式的位点"。M8 的策略选择据此
  只做**排序**（优先测有位点的故障类），不做**排除**（预算富余时仍补
  通用策略），见 方法V2_08 §3.3。

### 3.4 探针语料的双用途

同一批 1,646 探针在 Mode A 中服务两个测量（勿混淆分母）：

1. **基线盲区测量**（RQ 层面）：基线杀死率按故障类分解 → 哪类故障逃逸；
2. **策略受控验证**（映射层面）：每个被 CSE 杀死的探针记录 killing case
   → 聚合为 FaultToStressMap 的 closure_rate 证据。

## 四、架构与流程

```
                      candidate/original 源码
                              │
              ┌───────────────┴──────────────────┐
        （Mode A 离线）                     （Mode B 在线）
              │                                  │
   find_sites → apply → Mutant 探针        find_sites only
              │                                  │
   [M1] 编译执行（基线 + CSE）             SiteFingerprint JSON
              │                                  │
   killed/survived + killing case          [M8] 查 FaultToStressMap
              │                                  │
   [M7] closure_rate 聚合 ────────────────► 定向策略排序
```

## 五、桥接接口

| 方向 | 接口 |

## 六、与 V1 的差异摘要

| 维度 | V1 | V2 |
|------|----|----|
| 变异体语义 | 滑向"待验收对象" | 显式定义为故障探针（假设编码器） |
| find_sites 用途 | 仅离线变异前置 | + 在线位点指纹（零成本静态服务） |
| 算子↔故障类 | 隐含在文档 | 机器可读 1:1 映射，随代码发布 |
| 先验等价标记 | 归因时直接归 Type 1 | 降级为 EMD Layer 1 证据 + 指纹剔除依据 |

## 七、实现注意

1. `find_sites` 的双路径（Python AST + CUDA 字符串正则）继承 V1 全部
   过滤器（注释/字符串/模板/指针声明/GPU 配置行），指纹模块**不得**
   复制实现，直接 import 算子类调用；
2. Triton kernel 的指纹依赖 Triton 特有模式（`tl.program_id` 等），
   V1 算子已覆盖；对非 KernelBench 结构的候选（无 Model 类包装）需要
   一个轻量源码定位适配器（找到 kernel 字符串/函数体再扫描）；
3. 指纹的假阴性（新错误模式无对应算子）通过 M4 的分类学维护闭环缓解，
   并在论文 Threats 中声明；
4. 单元测试要求：对每个算子构造 ≥1 个含位点与 ≥1 个不含位点的最小
   源码样例，锁定 find_sites 行为；指纹输出对同一源码必须逐字节确定。
