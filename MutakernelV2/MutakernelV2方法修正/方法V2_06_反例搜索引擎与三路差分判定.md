## 一、问题背景

V1 的 "Phase II 五维增强测试" 同时承担了三件事却未区分：给变异体定生死、
给等价判断纠错（平反）、充当更强验证器。表现为四个具体口径缺陷：

1. `value_stress` 把 "allclose 通过但 bitwise 不同" 也计 KILLED——把
   "可区分"与"错误"混为一谈；
2. `config_stress` 在 reference 产生 NaN 时仍拿含 NaN 的 ref 与 mutant 做
   allclose（必然 False → 假阳性），与其他维度的 fallback 逻辑还不一致；
3. ref-NaN fallback（26% subject 触发、累计 1303 次）引入
   "original 输出即正确"的未验证假设；
4. 判定语义、被测对象、早停策略耦合在同一个脚本里，无法复用为在线验证器。

## 二、本模块拟解决的问题

提供一个**与被测对象无关**的反例搜索组件：

> 输入（被测程序 S、oracle 结构、契约、预算、case 计划），在五维行为空间
> （数值分布 × dtype × 执行模式 × 重复执行 × batch 配置）内搜索使 S 偏离
> oracle 的**契约内反例**；输出反例 / 未发现 / INCONCLUSIVE。

两种 oracle 结构：

- **三路（审计模式，M7 调用）**: S = mutant 探针，oracle = reference，
  control = original——反例须完成"错误由变异引入"的归因；
- **两路（验证模式，M8 调用）**: S = 原始候选内核，oracle = reference，
  无 control——反例直接推翻现有验证器的通过判定。

## 三、判定语义（本模块的核心贡献）

### 3.1 三路判定的三个基元

对每轮压力输入 x（均经契约校验）：

```
A := StrictCompare(R(x), O(x)) 在契约容差内   # original 是否正确
B := StrictCompare(R(x), M(x)) 在契约容差内   # mutant 是否正确
C := ExactEqual(O(x), M(x))                    # 逐位一致（NaN-aware）
```

三者均由 M1 严格 oracle 产出；A/B 各自可能为 INCONCLUSIVE（编译/超时/
oracle 不支持等），任何基元 INCONCLUSIVE → 该轮 verdict = INCONCLUSIVE。

### 3.2 五值判定表（唯一合法解释）

| A | B | C | verdict | 语义与去向 |
|---|---|---|---------|-----------|
| PASS | FAIL | （通常 false） | **SPEC_VIOLATION** | 变异引入正确性错误；生成 CounterexampleBundle；唯一计入盲区确认、平反、杀死统计 |
| PASS | PASS | false | **EXACT_DIVERGENCE_ONLY** | 推翻严格实现等价，不推翻契约等价；单独统计（量化容差内可区分行为的普遍度），不计缺陷 |
| PASS | PASS | true | **INDISTINGUISHED** | 该轮无差异；累积为等价的经验证据（永非证明） |
| FAIL | FAIL | * | **INVALID_INPUT** | 压力输入超出 original 的有效域，无法归因；单独计数，不判杀、不降等价证据 |
| FAIL | PASS | * | **ACCIDENTAL_REPAIR** | 变异意外修复/缓解 original 的问题（罕见）；不判杀；**转出为 original 自身隐藏缺陷线索**（回流 M8 语境） |

两路模式退化为 A′ := ok(R(x), K(x))：FAIL → 反例，PASS → 无发现，
基础设施 → INCONCLUSIVE。

### 3.3 与 V1 判杀口径的三个断裂点（重跑前必须清点影响面）

1. bitwise-only kill 全部改判 EXACT_DIVERGENCE_ONLY（含 tier1_replay 的
   条件 B）；
2. config 维度 reference 崩溃/无效 → INVALID_INPUT/INCONCLUSIVE，
   永不 fallback 到 original 当 oracle（original 在 off-contract batch 的
   正确性未验证，fallback 的前提不成立）；
3. 全维度废除 ref-NaN fallback，改为"合并方案"（2026-07-21 定案）：
   运行期用 NaN 位置感知比较（original 必须复现 ref 的 NaN 模式才构成
   有效对照，否则该轮作废）+ planning 期契约 value-domain 排除已知
   NaN 诱导输入（见 方法V2_01 §3.5、方法V2_02 §3.1）。

## 四、五个搜索维度（算法定义）

所有维度共享：case 由计划（M7/M8 产出）给定；每轮走 M1 `ExecuteCase`；
计划内轮次的实际执行数落盘（planned vs actual）。

### 4.1 value（数值分布）

```
for case in plan.value_cases:            # 策略 × seeds，去重见下
    obs ← ThreeWay(case)                  # 或 TwoWay
    record(obs)
    if obs.verdict == SPEC_VIOLATION and mode.early_stop_dimension: break
去重（仅审计模式）: EMD Layer 2 已 bitwise 一致的 (policy, seed) 跳过
   （bitwise 严格于 allclose，结论可迁移）；被跳过的轮次在预算账目中
   显式记为 "dedup_skipped" 而非静默消失。
```

### 4.2 dtype（精度切换）

```
for dtype in 契约授权 ∩ {float16, bfloat16}:
    for seed in plan.dtype_seeds:
        cast 模型与浮点输入到 dtype（nn.Module.to 为 in-place，见 V2-01 §六.2）
        比较容差用契约中该 dtype 的 atol/rtol
        "not implemented for Half" 类错误 → INCONCLUSIVE(oracle_unsupported)
```

### 4.3 training（执行模式）

```
适用性: 契约 modes.train.allowed ∧（审计模式下再按算子门控:
        {epsilon_modify, const_perturb, init_modify, arith_replace, cast_remove}）
不适用 → 记 not_applicable（区别于 survived/PASS）
执行: .train() 模式 + 全部 21 策略（不去重——执行模式不同，Layer 2 结论
      不可迁移）× plan.train_seeds
契约启用 backward 时: 三个冻结随机 VJP 的梯度同层比较（M1 §3.4 第 6 层）
```

### 4.4 repeated（非确定性）

```
for seed in plan.repeat_seeds:
    固定输入 x；连续调用 S(x) repeat_count 次（同一模型实例，状态连续）
    判定 1: 任一 trial 对 oracle 超容差 → 按 §3.2 判定（记录 divergent_trial）
    判定 2: 全部 trial 对 oracle 合格，但 trial 间自不一致
             （allclose(atol=rtol=1e-6, 来自契约 self_consistency)失败）
             → 若契约 determinism.bitwise_repeatable_required 或
               自不一致幅度超容差 → SPEC_VIOLATION(kind=nondeterminism)
             否则记 EXACT_DIVERGENCE_ONLY(kind=jitter)
    崩溃于第 k 次调用 → FAIL(candidate_crash)
设计要点: 跑完全部 trial 再判自不一致（保证统计完整性）
```

### 4.5 config（batch 配置）

```
for bs in 契约授权的 rebatch 值 ∩ {1,2,4,8,16,32,64}:
    for seed in plan.config_seeds:
        rebatch（仅契约声明的 batch 维；截断或 repeat+截断）
        reference 无效（异常/契约外 NaN）→ INVALID_INPUT，绝不 fallback
        审计模式仍需 A 基元（original 在该 bs 下必须先 PASS）
契约未授权 rebatch 的任务: 该维度 not_applicable；
如实验设计要求越界探索 → 整维度标 extended_contract 单列
```

### 4.6 tier1_replay（仅审计模式）

EMD Layer 2 记录过 bitwise divergence 见证的探针：优先复放
(seed, policy)，按 §3.2 全语义重判（注意断裂点 1：复放后仅 bitwise 差异
不再判杀）。无可复放见证（历史 worker 超时类）→ 直接进常规维度。

## 五、早停与预算策略（模式差异的唯一所在）

| | 审计模式（M7） | 验证模式（M8） |
|---|---|---|
| 维度内 | SPEC_VIOLATION 后停止该维剩余轮 | 同左 |
| 跨维度 | **不早停**（需要全维敏感性画像做逃逸机制归类与 leave-one-out） | **首个 SPEC_VIOLATION 即停**（deployment 档；评测档可配置跑全） |
| 连续超时 | ≥5 次跳过该维剩余轮（abort 原因落盘） | 同左 |
| 预算账目 | planned/actual/dedup_skipped 三本账 | planned/actual + 墙钟预算（可选） |

## 六、输出

- 每轮: `Observation` / `ThreeWayObservation`（V2-00 §3.3/3.4）；
- 每反例: `CounterexampleBundle`（V2-00 §3.5），生成时执行一次本地复放
  自检（`replay_verified`）；
- 每 subject: `EngineResult = {per_dimension: [...], first_violation,
  cross_dimension_confirmations, budget_ledger}`。

`cross_dimension_confirmations`（≥2 维独立产出 SPEC_VIOLATION）
是论文交叉确认率的直接数据源。

## 七、桥接接口

| 方向 | 接口 |
|------|------|
| M7 → M6 | `run_audit(probe, original, reference, contract, plan) -> EngineResult`（三路） |
| M8 → M6 | `run_validate(candidate, reference, contract, plan, early_stop) -> EngineResult`（两路） |
| M6 → M1 | 每轮 `ExecuteCase`；三路模式一轮内 (R,O) 与 (R,M) 两次成对执行 + O/M 精确比较 |
| M6 → M5 | SPEC_VIOLATION on LIKELY_EQUIVALENT → 平反回流 |
| M6 → M9 | CounterexampleBundle 是人工审计告警项的证据载体 |

## 八、与 V1 的差异摘要

| 维度 | V1 (Phase II) | V2 (CSE) |
|------|--------------|----------|
| 定位 | "处理 534 个 EMD 未关闭变异体的流程" | 对象无关组件，审计/验证两个调用方 |
| 判定 | killed/survived 二值 + bitwise 辅助判杀 | 五值语义，SPEC_VIOLATION 与 EXACT_DIVERGENCE 分离 |
| ref NaN | fallback 用 original 当 oracle | 废除；INVALID_INPUT/INCONCLUSIVE |
| config oracle | 与主轨道不一致（假阳性已知） | 与全维度统一，ref 无效即作废 |
| 早停 | 全局跨维不早停 | 模式化：审计不早停 / 部署首败停 |
| LLM 兜底 | 曾内嵌（后移除） | 不存在于引擎；LLM 只在 M5 triage |

## 九、实现注意

1. 历史 166 中 kill_type="bitwise" 与 ref_nan_fallback 相关 kill 的清点
   （思路文档 04 的 P0）决定论文数字变动幅度，必须先于重写完成；
2. 引擎不得直接读取 EMD/Tier/指纹——一切先验通过 `plan` 参数注入，
   保证组件可单测、可复用；
3. repeated 维度 30 次执行对低概率 race 的检出功效有限，论文 Threats
   保留该声明；契约可按任务提高 repeat_count；
4. 每维度的 not_applicable / extended_contract / INCONCLUSIVE 计数
   全部进入分母表——applicability 差异是 RQ4 各数据集解读的关键
  （V1 Table 9 的教训：低检出常是覆盖假象）。
