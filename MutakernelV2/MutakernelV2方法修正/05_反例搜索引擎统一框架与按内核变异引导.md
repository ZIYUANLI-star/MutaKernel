## 1. 按内核变异引导：完整逻辑

核心一句话：**变异分析是在为候选内核 K 定制一张"够格的考卷"，最后考的是 K 本人。**

### 1.1 五步流程（方案 b 原始形态）

以 LLM 生成、已通过 KernelBench 的 LayerNorm kernel K 为例
（含 `rsqrtf(var + 1e-5f)` 与 `__syncthreads()`）：

| 步骤 | 动作 | 产物/含义 |
|------|------|----------|
| 1. 探针生成 | 16 算子扫 K 源码：epsilon_modify → M1(eps→0)、M2(eps→1e-2)；sync_remove → M3 | 每个探针 = 一个假设"K 可能在此位置犯此类错"（RealismGuard 保证该假设现实） |
| 2. 现有测试考探针 | KernelBench 5 组 randn 测 M1-M3 | M1 被杀；M2 存活（var≈1，5e-3 差异被容差吸收）；M3 存活（单次执行无竞态） |
| 3. EMD 过滤 | 剔除等价探针（其存活不含盲区信息） | 保留 M2、M3 |
| 4. 盲区→定向测试 | M2 逃逸机制=输入方差远离 0 → near_zero；M3=单次执行 → repeated_run；验证新测试确实杀死对应探针 | 证明"该策略对该故障类有效"（仍不给任何对象定罪） |
| 5. 考 K 本人 | 用补强测试跑 **K vs reference**（探针退场） | 偏离 → 反例，拒绝 K；全过 → 带充分性证明的接受 |

**第 2 步的正确读法（全流程关键）**：M2 存活 ≠ "M2 是坏 kernel"，而是
"**如果 K 在这个位置犯了这类错，现有测试发现不了**"。存活探针度量的是
现有测试相对于 K 这份具体代码的盲区——探针是温度计，量的是考卷水平。

**第 5 步全过的价值**：不是裸 PASS，而是"已证明考卷能检出 K 的代码位点上
可能出现的故障类，K 仍通过"——即经典变异测试的 mutation adequacy 语义。
这是对 Reviewer A"为何不直接审计真实 kernel"的最深回答：
直接审计只能报告"找到几个错"，无法回答"没找到错时该不该信"；
变异充分性提供了**停止准则**。

### 1.2 成本与三个实现方案

第 1-4 步需编译运行每个探针（CUDA JIT 每个数分钟、每 kernel 数十探针），
在线逐候选执行不可承受。

| 方案 | 做法 | 在线成本 | 与 RQ4 历史数据 |
|------|------|---------|----------------|
| (a) 全量固定套件 | 不看考生，全套策略都上（现有 RQ4 的跑法） | 中 | 一致 |
| (b) 在线推导考题 | 每候选完整跑 1-5 步 | 不可承受 | 不一致 |
| (b′) 按任务摊销 | 每任务对首个过基线的候选做一次完整分析，定向测试缓存复用 | 摊销后可承受 | 部分兼容；工程复杂、跨候选位点不全同 |
| **(c) 在线查表选题（推荐）** | 离线研究建好并验证 fault-to-stress 表；在线用 `find_sites()` 静态扫 K 的故障类位点（毫秒级），查表选择/排序策略 | 低 | 兼容（(a) 是其无先验退化形式） |

方案 (c) 成立的前提："逃逸机制 → 有效策略"**跨 kernel 稳定**
（eps 类故障靠 near_zero、sync 类靠 repeated_run……），
这正是离线研究在 1,646 探针语料上已经建立并受控验证过的东西。
在线唯一需要按 kernel 回答的问题是"K 里有哪些故障类的位点"，静态可答。

## 2. Phase II 两条线的统一：一台引擎，两种调用

```
        反例搜索引擎（五维压力 + 三路差分 oracle）
        ——组件本身与"被测对象是谁"无关——
                    │
    ┌───────────────┴────────────────┐
 调用方式一：审计模式               调用方式二：验证模式
 X = 变异探针（带 original 对照）    X = 原始候选内核（无对照）
    │                                │
 反例同时完成两件事：                反例 → 拒绝候选内核
  ① 确认 validator 盲区，              （="更强验证器"线）
    受控验证 fault-to-stress 映射
  ② 探针曾被 EMD 判可能等价
    → 平反：false equivalent, q_post=0
      （="平反"线）
```

三点关键认识：

1. **平反不是独立线路，是审计模式反例按 EMD 先验分层后的子集。**
   同一个反例（original 通过 + mutant 违反参考语义）落在
   candidate_equivalent 上就多一层"EMD 先验被反证"的含义
   （历史数据：264 个里被杀 21 个）。方法上不为它单设流程。
2. **平反服务于测量可信度，不服务于验证器本身**：
   (a) 给 EMD 校准提供最有价值的带标签负样本（q_pre 高却被杀）；
   (b) 保护盲区测量的内部效度——用事实证明 survived ≠ equivalent，
   堵死"gap 数字里混等价噪声"的审稿攻击。
   口径纪律：仅 specification violation 计平反成功（见 01 文档）；
   仅 bitwise 差异只推翻严格等价。
3. **"更强"靠三段证明结构，不靠数字大**：
   受控段（已知故障上关闭盲区 + 逃逸机制归因）→
   对照段（同预算优于朴素增强，RQ2）→
   自然段（真实 kernel 上被独立确认的契约内缺陷，RQ1/RQ4）。
   审计模式供第一段，验证模式供第三段，桥 = fault-to-stress 映射表。

## 3. 对 MutaKernel 方法的具体修改（五条）

1. **Phase II 更名重切**：不再定义为"处理 EMD 未关闭的 534 个变异体的流程"
   （旧 Section 5 写法，Reviewer A 批评来源）。定义为对象无关的
   **反例搜索引擎**：输入（被测程序、oracle、契约、预算），
   输出（反例 / 未发现 / INCONCLUSIVE）；审计 harness 与候选验证器
   是两个调用方；Figure 3 拆为两图。
2. **平反并入审计输出口径**：审计模式 kill 按 EMD 先验分层报告，
   candidate_equivalent 上的 kill 标注 "EMD false equivalent"，
   并回流为 EMD 校准负样本。平反从"一条线"降格为
   "一个报告字段 + 一条数据回流"。
3. **Tier 机制归位并与位点匹配对偶**：Tier 1/2/3（按 EMD 证据分配预算）
   只属于审计模式；部署模式的预算分配由方案 (c) 位点匹配承担。
   两者是"**先验引导预算**"同一思想的两个实例
   （审计先验 = EMD 证据；部署先验 = 探针位点）——论文可用此统一表述。
4. **验证模式增加位点定向层**（方案 c）：在线静态扫位点 → 查表 →
   选择/排序策略；RQ2 矩阵新增消融行
   "位点定向选择 vs 全量固定套件（同预算）"，差值 = 变异指导的净贡献。
   （此行需补进 `configs/fse_strategy_matrix.json`，
   实现只需复用算子的 `find_sites()` + 一张映射表。）
5. **接受判定表述升级**：候选全过时报告 "PASS + 已覆盖故障类清单"
   （K 的位点涉及哪些故障类、每类用了哪些已验证策略），
   把 mutation adequacy 语义带进部署结论，
   同时满足"未找到反例 ≠ 正确"的措辞纪律。

## 4. 与现有 FSE 代码的衔接缺口

- `scripts/_candidate_worker.py` 目前无位点匹配层：需要新增一个
  轻量模块（静态调用 16 算子的 `find_sites()`，输出 K 的故障类位点画像），
  并在 planner 中按画像生成/排序策略 case——注意这会引入
  "不同 subject 的测试计划不同"，与预注册配对比较的关系要在
  协议中说明（定向行按位点画像预注册，仍然确定性、可复现）；
- `configs/fse_strategy_matrix.json` 需新增 `site-directed` 策略行
  （budget_matched, 32 calls），其 case 列表由位点画像动态派生但
  规则预先冻结；
- 审计模式输出 schema 增加 `emd_prior_tier` 与 `false_equivalent` 字段
  （对应第 2 条修改）。
