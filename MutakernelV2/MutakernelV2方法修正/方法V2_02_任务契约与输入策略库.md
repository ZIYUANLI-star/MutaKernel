# 方法 V2-02: 任务契约（Contract）与输入策略库（PolicyBank）（M2）

> **版本**: 2.0-draft-1（2026-07-21）
> **对应代码**: `src/experiments/contract.py`、`src/stress/policy_bank.py`、
> `configs/fse_strategy_matrix.json`
> **对应论文位置**: Section 3.x（Correctness Contracts）+ Section 5.x（Stress Policies）

---

## 一、问题背景

### 1.1 没有契约，就没有"契约内缺陷"

V1 的一个隐性缺陷：判定"kernel 在输入 x 下错了"之前，从未显式回答
"x 是不是该 kernel 有义务正确处理的输入"。后果具体化为三处：

1. RQ4 有 12 个告警只依赖 config/dtype 单维——若任务本就不承诺非默认
  batch 或 fp16，这些是**契约外发现**，混入缺陷数即夸大；
2. ref-NaN fallback：极端输入让 reference 自己产生 NaN，说明该输入很可能
  超出任务的有效值域，V1 却用退化 oracle 继续判杀；
3. 审计中 `requires_config_change` 占 67/392 轮级 verdict——大量"可杀性"
  争议本质是契约边界争议。

### 1.2 策略即测试语义，必须确定、有据、可复现

V1 的 21 个策略实现存在 dtype 不感知（fp16 下 near_overflow 直接 inf）、
非稠密布局破坏（`.view` 假设连续）、非确定性残留等问题；策略与故障类的
对应关系只存在于文档表格，未形成机器可读的映射。

## 二、本模块拟解决的问题

1. 为每个任务提供**可执行、版本化、冻结先于观测**的正确性契约：
   planning 时拒绝越权 case，运行期校验输入合法性，使
   `IN_CONTRACT_DEFECT` 与 `EXTENDED_CONTRACT_FAILURE` 可机械区分；
2. 提供 21 个**确定性、dtype 感知、布局保真**的数值分布策略与 4 类
   执行上下文变换，并携带机器可读的目标故障类元数据（供 FaultToStressMap
   与位点定向选择消费）。

## 三、契约设计（Contract Schema v1）

### 3.1 Schema

```json
{
  "contract_version": "1",
  "contract_id": "规范化 JSON 的 sha256",
  "arguments": [
    {"position": 0, "kind": "tensor",
     "shape": ["B", 512],
     "dims": {"B": {"kind": "batch", "min": 1, "max": 64, "default": 128}},
     "dtypes": ["float32", "float16", "bfloat16"],
     "value_domain": {"kind": "real", "min": null, "max": null,
                       "finite_only": true,
                       "exclusions": ["ref_nan_inducing"]},
     "layout": {"contiguous_required": false, "aliases": []}
    }
  ],
  "modes": {"eval": true, "train": {"allowed": true, "backward": true},
             "repeated": {"allowed": true, "max_repeat": 10},
             "config": {"rebatch_dims": ["B"]},
             "layout": {"noncontiguous_allowed": true}},
  "determinism": {"bitwise_repeatable_required": false},
  "oracle": {"atol": {"float32": 1e-4, "float16": 1e-2, "bfloat16": 1e-2},
              "rtol": {"float32": 1e-4, "float16": 1e-2, "bfloat16": 1e-2},
              "self_consistency": {"atol": 1e-6, "rtol": 1e-6}},
  "policy_bindings": {"near_zero": {"applicable_args": [0]},
                        "…": {}}
}
```

要点：

- **符号维度**：shape 用符号（"B"）声明哪些维可变、范围多少；
  `config` 模式只允许对声明为 batch 的维 rebatch；
- **dtype 感知容差**：来自 KernelBench 原生实现的先例
  （fp32 用 1e-4、fp16/bf16 用 1e-2），禁止全局 1e-2；
- **value_domain.exclusions**: `ref_nan_inducing` 声明"使 reference 产生
  非契约 NaN/Inf 的输入不属于有效测试域"——这是废除 ref-NaN fallback 的
  契约学基础。实现上：planning 时按任务先验排除已知 NaN 诱导策略；
  运行期 reference 仍产生契约外 NaN → INCONCLUSIVE(reference_failure)；
- **schema v1 边界**（显式声明，不近似）：仅支持顶层位置张量参数与默认
  stream；嵌套/关键字/标量约束、并发 stream 留待 v2。不满足的任务
  进入 unsupported 分层报告。

### 3.2 契约的生命周期纪律

```
撰写（任务规格 + reference 语义 + 数据集文档）
  → 双人评审签核 → 规范化 + hash → 冻结（先于任何检测器结果的揭示）
  → planning 校验（拒绝未授权 case）→ 运行期校验（入参逐条验证）
  → 结果按 in_contract / extended_contract 分层
```

冻结先于观测是防"按结果改契约"的预注册纪律；扩展契约测试（如对只承诺
fp32 的任务测 fp16）允许执行，但结果永远单列为 `EXTENDED_CONTRACT_FAILURE`，
不进主缺陷统计。

## 四、策略库设计（PolicyBank v2）

### 4.1 统一函数签名与四条实现不变式

```
policy(template_inputs: list, seed: int, ctx: PolicyContext) -> list
# ctx 携带: 目标 dtype 的 finfo（max/tiny/eps）、契约的 applicable_args
```

| 不变式 | 含义 | 实现要求 |
|--------|------|---------|
| I1 确定性 | 同 (template, seed) 输出逐位相同 | 内部 generator 显式 `manual_seed(seed)`，禁用全局态 |
| I2 dtype 感知 | 常数按目标 dtype 的 finfo 缩放 | 如 near_overflow 用 `0.5*finfo(dtype).max` 而非硬编码 1e30 |
| I3 有限性 | 除非策略显式声明，输出不含 NaN/Inf | 生成后 `assert isfinite` |
| I4 布局保真 | 保持 shape/dtype/stride/storage 拓扑 | 用 `copy_` 写入同布局副本，禁 `.view`/`.reshape` 重建 |

仅对契约 `policy_bindings` 声明的参数位施加变换；整型/布尔参数原样保留。

### 4.2 21 策略总表（数值定义 + 目标故障类）

设 `g = randn_like(x, generator)`，`F = finfo(dtype)`：

| 族 | 策略 | 数值定义 | 目标故障类 | 依据 |
|----|------|---------|-----------|------|
| 极端分布 | large_magnitude | g × 1e3 | F-ARITH, F-STAB, F-SYNC | FPGen |
| | extreme_magnitude | g × 1e6（按 F.max 截断） | F-STAB, F-CAST | FPGen |
| | near_overflow | g × 0.5·F.max | F-STAB, F-CAST | FPGen |
| | near_zero | g × 1e-7 | F-EPS, F-SCALE | FPGen |
| | denormals | g × F.tiny | F-EPS | FPGen |
| | near_epsilon | U(1e-7, 1e-5) | F-EPS | FPGen |
| | mixed_extremes | 50% ×1e4 + 50% ×1e-4 | F-PREC-ACC, F-CAST | Laguna SC'24 |
| 边界/符号 | all_negative | −|g| × 100 | F-INIT | BVA |
| | all_positive | |g| × 100 | F-INIT, F-STAB | BVA |
| | boundary_last_element | g，末位=1e4 | F-BOUND, F-LAUNCH | BVA |
| | relop_boundary_hit | arange % 10 | F-RELOP | BVA |
| 稀疏梯度 | dense_nonzero | |g| + 1.0 | F-ARITH | pilot |
| | sparse | 90% 零 + 10% g×100 | F-BOUND, F-IDX | BVA |
| | sparse_extreme | 99% 零 + 1% ×1e4 | F-BOUND | BVA |
| 结构位置 | structured_ramp | linspace(0,1,n).reshape_as | F-IDX, F-BCAST, F-LAYOUT, F-LAUNCH | Mu2 |
| | head_heavy | 前 25% 极端 + 其余近零 | F-IDX | Mu2 |
| | tail_heavy | 后 25% 极端 + 其余近零 | F-IDX, F-BOUND | Mu2 |
| 归约对抗 | alternating_sign | 交替 ±100 | F-RED-ORD | Higham |
| | reduction_adversarial | 交替 ±1e4 + 微噪声 | F-RED-ORD, F-PREC-ACC | Higham |
| | uniform_constant | 全 88.0 | F-SCALE | Magneto |
| | init_sensitive | 随机整体全正或全负（由 seed 决定） | F-INIT | pilot |

`target_fault_classes` 作为策略元数据随代码发布（机器可读），
是 FaultToStressMap 的先验骨架；审计模式（M7）产出的实测 closure_rate
最终校准/覆盖这一先验。

### 4.3 执行上下文变换（不属于策略库，属 case.mode）

| mode | 变换 | 约束 |
|------|------|------|
| eval | 默认 | — |
| train | `.train()` + 契约允许时构造反向（3 个冻结随机 VJP） | 仅契约 `modes.train.allowed` |
| config | 对声明 batch 维 rebatch ∈ {1,2,4,8,16,32,64} ∩ 契约范围 | rebatch = 截断或 repeat+截断，0-D/非声明维不动 |
| repeated | 同一输入连续调用 repeat_count 次（同一模型实例，状态连续） | 契约 `max_repeat`；自一致性用 oracle.self_consistency 容差 |
| layout | 输入替换为同 shape 非连续视图（expand/transpose 构造） | 契约 layout 允许时 |

## 五、架构与流程

```
契约撰写/评审 ──► contract.json（冻结+hash）
                        │
   planning（M7/M8）────┤ validate: case ∈ 契约授权集?  否 → 拒绝/单列
                        ▼
   ExecuteCase（M1）── PolicyBank.apply(policy, template, seed, ctx)
                        │            └ 违反 I1–I4 → 单元测试期即失败
                        ▼
   运行期入参校验（shape/dtype/finite/layout ∈ 契约）→ 违反 → contract_violation
```

## 六、桥接接口

| 消费方 | 接口 |
|--------|------|
| M1 | `Contract.validate_case(case)`、`Contract.validate_inputs(args)`、`oracle` 容差表 |
| M6 | case 合法性预检；`policy_bindings` 决定 applicable 分母 |
| M7 | 审计计划按契约授权生成；`config`/`dtype` 越界 case 自动归 extended_contract |
| M8 | 策略元数据 `target_fault_classes` 是位点定向选择（方法V2_08）的查表键之一 |
| M9 | 每条人工审计标签必须引用违反的契约条款字段（`violated_clause`） |

## 七、与 V1 的差异摘要

| 维度 | V1 | V2 |
|------|----|----|
| 契约 | 隐式（KernelBench 固定 shape 惯例） | 显式 schema v1，冻结先于观测，双人签核 |
| 容差 | 全局 atol=rtol=1e-2 | dtype 感知，来自契约 |
| 越界测试 | 与契约内混计 | extended_contract 单列 |
| 策略实现 | dtype 不感知、可破坏布局 | I1–I4 四不变式 + 单元测试锁定 |
| 策略↔故障类 | 文档表格 | 机器可读元数据 + 审计实测校准 |

## 八、实现注意

1. 契约撰写是 90 任务 × 人工工作，量最大；优先复用 KernelBench 的
   get_inputs/get_init_inputs 推导默认值，仅边界子句需人工判断；
2. `ref_nan_inducing` 排除集合初始为空，由 pilot 运行的
   reference_failure 记录迭代填充，每次填充是契约版本升级（记录变更原因）；
3. 策略常数表（1e3/1e6/0.5·max…）整体作为 `policy_bank_version` 的一部分
   进 run manifest；改动任何常数即版本升级；
4. rebatch 的 repeat+截断可能引入样本重复相关性，对 BatchNorm 类任务的
   统计量有影响——在契约的 config 子句写明该语义并在论文 Threats 提及。
