## 1. 投稿定位的转变

| 维度 | V1 (EuroSys) | V2 (FSE) |
|------|-------------|----------|
| 论文类型 | 系统论文（新验证器系统） | 实证软件工程论文（empirical study + methodology） |
| 核心主张 | "MutaKernel 是更强的验证器" | "被独立审计的 LLM-GPU-kernel 验证器误接受实证研究 + 预算匹配的验证策略对比 + 变异分数对自然缺陷的预测效度" |
| 开销评测 | 一等公民（系统审稿硬门槛） | 折叠进 RQ2 预算匹配对比（每确认缺陷的 GPU 秒、首反例时间、Pareto 前沿），不再单独作为系统贡献 |
| 建议标题方向 | — | "When Passing Is Not Correct: An Empirical Study of Correctness Validation for LLM-Generated GPU Kernels" |

**开销削弱的评估**：转投 FSE 后弱化"美元成本/ADRS 吞吐"叙事是合理的，但注意它并
没有被删除——预算匹配本身就是成本控制变量，`analyze_fse_statistics.py` 仍输出
detection/cost Pareto。FSE 审稿人同样会问"是不是只是多跑了测试"，所以 RQ2 的
equal-call + equal-GPU-time 双口径是 V2 无论投哪里都必须保留的骨架。

## 2. V2 的统一叙事：Diagnosis-to-Validation

全文只回答一个核心命题：

> KernelBench 式验证器把五维正确性行为空间（数值分布 × dtype × 执行模式 ×
> 重复执行 × batch 配置）压缩在单个默认采样点上，因此真实存在的故障可能没有被
> 激活、感染、传播或观察到。我们系统地**测量**这些盲区，并检验由盲区诊断导出的
> 定向压力策略是否优于同预算的朴素增强。

两种运行模式必须在图和文字上彻底分离（直接回应 Reviewer A 第 3 条）：

- **Mode A（离线审计/元评估）**：输入 = reference + original + mutant 三元组，
  组件 = 变异生成、EMD 置信度、压力反例搜索、独立人工审计、逃逸机制分析；
  产物 = validator 盲区测量 + fault-to-stress 映射。
- **Mode B（在线候选验证）**：输入 = candidate + reference + 契约 + 预算，
  组件 = 压力引擎 + 差分 oracle；输出 = PASS / FAIL / INCONCLUSIVE。
  **不含**任何 mutation、EMD、Tier、等价标签（已由 `scripts/_candidate_worker.py`
  在代码上落实）。

两模式之间唯一的箭头：`诊断出的逃逸机制 → 导出压力维度`。

### 2.1 待验证对象的重心修正（2026-07-21，据 GPT5.6sol 网页版讨论补充）

一个必须贯穿全文的定位（作者在讨论中的关键纠正）：

> **最终待验证对象自始至终是"已被现有验证器判定通过的原始候选内核"；
> 变异体只是围绕它构造的故障探针，用于暴露现有测试的盲区、指导定向压力
> 测试的生成。变异体本身从来不是被验收的目标。**

由此产生一个架构决策点——变异对测试生成的"指导"发生在哪一层：

| 方案 | 在线成本 | "为何需要变异"的回答力度 | 与现有 RQ4 数据 |
|------|---------|------------------------|----------------|
| (a) 固定压力套件（FSE 代码现状）：变异只在离线研究中出现一次，在线跑固定策略矩阵 | 低 | 较弱（变异像一次性研究） | 一致 |
| (b) 按内核在线变异引导：每个候选生成/编译/运行变异探针再生成测试 | 高（JIT 每变异体数分钟，ADRS 循环不可承受） | 强 | 不一致（222 不是这么跑出来的） |
| **(c) 折中（推荐）：离线变异研究产出 fault-to-stress 映射；在线只做静态探针位点匹配** | 低（毫秒级） | 强（变异是测试选择引擎） | 兼容（固定套件是其无先验退化形式） |

方案 (c) 的做法：复用 16 个变异算子现成的 `find_sites()`（正则/AST 静态分析），
检测候选内核中存在哪些故障类别的位点（如含 softmax 模式 → stab_remove 探针
适用 → 优先 near-overflow/near-zero 策略），据此**选择和排序**压力策略，
不在线执行任何变异体。这同时给 RQ2 提供一个新的消融对照：
同预算下"位点定向选择"vs"全量固定套件"，直接量化变异指导的净贡献。

## 3. RQ 结构（采纳 FSE_REVISION_PLAN，补充一处）

| RQ | 问题 | 备注 |
|----|------|------|
| RQ1 | 真实的、被基线接受的 LLM 生成 kernel 中，有多少存在**契约内已确认缺陷**（confirmed false-acceptance lower bound）？故障类别如何分布？ | 正面回应 Reviewer A"为什么不直接审计真实 kernel"——V2 直接做了 |
| RQ2 | 同等 candidate 调用预算 / 同等 GPU 时间下，默认随机、更多种子、多样化随机、边界值、dtype/mode/config 压力、MutaKernel 策略套件的确认缺陷召回、告警精度、成本各如何？ | 预注册 32 调用矩阵已冻结在 `configs/fse_strategy_matrix.json` |
| RQ3 | 变异分类学与变异分数能否预测自然 LLM 缺陷的检出？哪些算子有代表性、哪些没有、哪些自然故障类缺失？ | 这是"为什么还需要变异实验"的正面答案；允许诚实的负结果 |
| 次级案例 | TaskD 修复实验（104/101 队列对齐 + no-fallback 守卫后才可保留） | 不作主 RQ |

**V2 需补强的一处**：FSE 计划把严格性做满了，但"正向故事"偏弱。变异研究的最终
产物不是 mutation score，而是**"故障类别 → 逃逸机制（RIPR：激活/感染/传播/观察）
→ 缺失观察轴 → 定向压力策略"这张映射表**。RQ3 的预测效度分析应配套一节
escape-mechanism 归类分析，否则 21 个策略在论文里仍然像"随便多测了一些东西"。
这张映射表也是回应 Reviewer C"taxonomy 如何维护扩展"的钩子：新故障模式 →
归类管线 → 新算子/新策略 → 受控注入验证，形成闭环。

## 4. 对 GPT5.6sol 已有改版的总体评价

**方向正确、根据充分的部分**（经本轮代码比对独立核实）：

1. **Phase I 状态污染是真实存在的 soundness bug**：旧 `mutant_runner.run_mutant`
   连续实例化 `Model` 与 `ModelNew`，中间不重置 RNG、不同步参数——凡带随机初始化
   参数的任务（L2 大量 Linear/Conv/BN），ref 与 mutant 权重不同，输出差异与变异
   无关也会被计为 kill。历史 L2 杀死率 454/506（89.7%）显著高于 L1（485/977，
   49.6%），与污染假设一致。**这一发现使"全部 1,646 变异体必须重跑"的要求成立**，
   历史 939/534/166/168 都要降级为 pilot 数字。
2. 旧 Phase II `sync_weights` 默认未启用，且回退同步按形状顺序拷贝参数（不按名
   字），同样不安全——已核实旧 `_stress_worker._sync_weights` 确有按序拷贝分支。
3. 在线验证与变异解耦（`_candidate_worker.py` + contract + budget）精确命中
   Reviewer A 第 3 条。
4. 三值结果（PASS/FAIL/INCONCLUSIVE）、可执行契约、冻结 manifest、盲审协议、
   任务聚类 bootstrap + McNemar + Holm 的统计方案，符合 FSE 实证标准。
5. `LEGACY_RESULT_VALIDITY.md` 对每个历史数字的分级（HISTORICAL_REPRODUCIBLE /
   PILOT_ONLY / REQUIRES_RERUN / DO_NOT_CLAIM）是诚实且必要的，还发现了此前没
   注意到的队列冲突（831/64 vs 834/67、1,646 vs 1,663、104 vs 101）。

**需要警惕/收缩的部分**（本轮的独立判断）：

1. **门槛过多导致停摆风险**。Runbook 的 Gate 0（沙箱+可信控制器+容器摘要冻结）
   超出 FSE artifact 的常规期望。建议：把"对抗恶意 candidate 的 reward-hacking
   主张"从论文主张里删掉或降级为讨论，即可把 Gate 0 收缩为"非 root + 无凭据 +
   容器隔离"的常规水平，凭据轮换仍是硬前提。
2. **32 调用预算显著弱于历史 MutaKernel 协议**（历史 value_stress 单维就 45–75
   轮；repeated 从 10 次降为 2 次；config 从 7 个 batch 降为 4 个）。预算匹配行
   变弱是公平比较的代价，可以接受，但**必须保留"unrestricted native MutaKernel
   full-suite"一行**（fairness gates 已允许三视图），否则论文失去与历史结果和
   RQ1 审计的连接。
3. **严格 planner 会显著缩小配对队列**（任一 subject 缺任一矩阵能力即整体拒绝，
   例如 dtype 不兼容的 reference 在 AI-CUDA-Engineer 占 180/222）。RQ1 需要的
   population/applicability planner 尚未实现，是当前最大的代码缺口之一。
4. **train 模式加 backward VJP 检查扩大了范围**。历史 training_stress 不做反向；
   新矩阵 `requires_backward: true` 会让大量不支持反向的 candidate 变
   INCONCLUSIVE。需要契约按任务门控，且在论文中明确 backward 属于扩展贡献。
5. **建议增加一个低成本的"污染定量"先导实验**（详见 04 文档）：全量重跑前，先
   用修正后的 runner 重跑分层样本（重点 L2），测量历史 kill 的翻转率。若 L1 翻
   转率很低，历史 L1 结论可作为敏感性核验过的 pilot 保留叙述价值；同时翻转率
   本身就是论文里"harness soundness 影响测量结论"的一个有说服力的观测。

## 5. V2 成败的三个必要条件（重申）

1. 叙事：两模式分离 + fault-to-stress 因果链讲清（图 A/图 B 双图）；
2. 严格性：判杀口径拆分 + 等价置信度 + 双盲审计（01/02 文档）；
3. 实证：预算匹配强基线 + 独立标注的自然缺陷下界 + 预测效度（03 文档）。

三者缺一，换会场也仍是 weak reject。
