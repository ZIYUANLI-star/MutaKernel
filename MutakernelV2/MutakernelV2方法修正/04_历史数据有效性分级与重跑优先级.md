## 2. 历史数字的处置（与 LEGACY_RESULT_VALIDITY 对齐）

核心原则：**历史检测器告警 ≠ 已确认缺陷；LLM 判定 ≠ 等价证明；检测器筛过的
队列 ≠ 独立审计样本。**

| 历史数字 | V2 处置 |
|---------|---------|
| 939 / 63.75% / 77.67% | Phase I 状态污染（ref 与 mutant 初始化 RNG 不同步）已证实，全部 1,646 需重跑；旧数保留为 pilot |
| 534 → 166 / 99.82% | 166 个检测阳性在 368 审计前被移出审计池（resubstitution），99.82% 不得再作 headline；新队列须由重跑后的 Phase I 机械导出 |
| 222 | 只能称 "stress-flagged"，须独立人工审计后才有确认缺陷数；12 个仅依赖 config/dtype 单维的告警须按契约重新归类 |
| 104 / 90 / 15 | 104 vs 101 队列对齐前，86.5%/14.4% 均为 pilot 观测 |
| KGB 699/248 | PILOT_ONLY，不得与主 166/222 合并 |

## 3. 重跑优先级建议（本轮独立提出）

**P0（重写论文前，1–2 天，无 GPU 也可开始的部分）**
1. TritonBench-G ±1 与 831/834、104/101、1,646/1,663 四处队列对账（纯数据工作）；
2. 历史 Phase II kill 中 kill_type="bitwise" 的清点（判杀口径拆分的影响面，
   见 01 文档）；ref_nan_fallback 相关 kill 的清点。

**P1（第一个 GPU 实验，强烈建议在全量重跑前做）**
3. **状态污染定量先导**：用修正后的 runner 重跑 Phase I 的分层样本
   （L1/L2 各若干 kernel × 全部算子），测量历史 kill/survive 的翻转率。
   目的：(a) 校准全量重跑的预期与成本；(b) 翻转率本身是论文中
   "harness soundness 影响测量结论" 的一手证据；(c) 若 L1 翻转率低，
   历史 L1 pilot 的叙述价值可以保留。

**P2（主实验，依赖 Gate 0 凭据轮换 + 契约冻结）**
4. 全量 1,646 变异体重跑（修正 runner）→ 机械导出新 Phase II 队列；
5. 自然 kernel 帧（597 名义）重跑 + RQ2 预算匹配矩阵；
6. 双盲人工审计（人群 A/B 并行启动，先跑 20–30 条 pilot 校准码本）。

**P3（补充）**
7. 人群 C（1,020 失败样本重编码，RealismGuard 定量化——当前纯缺口）；
8. TaskD 重跑（no-fallback 守卫 + 独立 oracle）或降级为讨论；
9. KGB 若保留，须同协议重跑。

## 4. 数据存放约定

- 本目录 `重跑实验数据/` 存放 P1–P3 的重跑输出；`补充实验数据/` 存放 V2 新增
  实验（预算匹配矩阵、人工审计标注、外部基线对比等）；
- 每份数据必须带 run manifest（commit、环境指纹、契约/策略版本、种子、预算）；
- 历史目录保持不可变，禁止原地改 JSON 使总数吻合，禁止新旧 checkpoint 混合汇总。
