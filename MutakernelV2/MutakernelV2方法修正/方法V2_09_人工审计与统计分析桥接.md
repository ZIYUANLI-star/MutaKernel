## 一、问题背景

V1 的两类硬伤都发生在"检测器输出 → 论文声明"的最后一公里：

1. **循环/复代入**：534 中先移出 166 个检测阳性再审计余下 368，
   用同源标签评估同一检测器（99.82% 由此不可作 headline）；
2. **告警 ≠ 缺陷**：RQ4 的 222 个 stress-flagged 从未独立确认，
   且混入 12 个 config/dtype 单维（可能契约外）告警。

GPT5.6sol 已建好队列/汇编/统计三件套工具与协议文本；V2 需要的是把
M5/M6/M7/M8 的产出**以正确的时序与盲化形态**接进这套工具，并冻结统计口径。

## 二、本模块拟解决的问题

1. 定义四个审计人群（A 自然内核 / B 探针等价 / C 分类学 / D 修复）与
   各模块产出的映射及队列生成时序；
2. 定义**政策中立盲审证据包**的构成（当前工具链的最后一个阻塞：
   replay config 暴露 policy/seed 元数据）；
3. 冻结统计分析的输入契约与主口径清单。

## 三、方法设计

### 3.1 四人群与模块产出的映射

| 人群 | 对象 | 队列来源 | 标签 schema（关键字段） |
|------|------|---------|------------------------|
| A 自然内核 | RQ1/RQ4 的真实候选 | M8 evaluate 告警 ∪ 执行未决 ∪ 全 PASS 分层阴性抽样（封存后生成） | subject 级: DEFECT_CONFIRMED / NO_DEFECT_FOUND / INCONCLUSIVE；告警级: 确认与否 + fault_class + violated_clause + replay_status |
| B 探针等价 | M7 审计队列的探针 | 重跑后新队列的全量或预注册分层金集（标注者不见 EMD 等级/CSE 结果/历史标签） | NON_EQUIVALENT / EQUIVALENT_MACHINE_PROVEN(仅复核) / LIKELY_EQUIVALENT / INCONCLUSIVE |
| C 分类学 | 1,020 失败样本 + 已确认自然缺陷 | M4 §3.2 编码管线（复用本模块标注工具） | root_cause ∈ 码本 + mapped_operators ∪ {not_represented} |
| D 修复 | TaskD 队列（104/101 对齐后） | 修复输出 + 结构守卫结果 | REAL_FIX / PARTIAL / FALLBACK_CHEAT / DEAD_KERNEL / NOT_FIXED / INCONCLUSIVE |

铁律：四人群标签互不借用；任何人群的标签不得回改上游队列或预算。

### 3.2 时序协议（消除循环的机械保证）

```
检测器（CSE/Validator）全部完成
  → 观测日志 + run manifest 封存（digest 链）
  → build_human_audit_queue 绑定精确 run：
      全部告警 + 全部未决 subject + 阴性分层抽样（预注册 seed）
      queue 项使用中立 ID；detector/policy 映射进 sealed_mapping（隔离存放）
  → 双人独立标注（A/B 锁定前互不可见）→ 仲裁 C → compile_human_audit
      （kappa/混淆矩阵在仲裁前计算）
  → analysis_labels 锁定 → 才允许计算任何 "confirmed" 口径
```

### 3.3 政策中立盲审证据包（当前唯一阻塞的规格）

标注者能看到的（per 告警项）：

```
{ "queue_id": "中立 ID",
  "candidate_source": "…", "reference_source": "…", "contract": {…},
  "materialized_inputs": "safetensors（具体张量值，可直接加载复算）",
  "observed_outputs": {"reference_digest": …, "candidate_digest": …,
                        "diff_summary": {max_abs, max_rel, first_index}},
  "replay_program": "自包含脚本: 加载 materialized inputs → 双跑 → 比较",
  "execution_context": {"mode": "train|eval", "dtype": "…", "batch": …} }
```

**必须移除**：策略名、seed、维度名、检测器身份、EMD 等级、q_pre、
历史论文标签。`execution_context` 保留（标注者判断契约内与否需要它），
但以中立字段名出现，不出现 "near_zero" 等策略语义名。
实现即 `CounterexampleBundle → BlindBundle` 的一个纯导出函数 +
fresh-container 复放自检。

### 3.4 统计口径（冻结清单）

输入契约：`analyze_fse_statistics.py` 只接受
（run manifest + 冻结 plan + 完整观测 + 锁定标签 + agreement 报告）
五元组，digest 链校验失败即 fail-closed。主口径：

| 口径 | 定义 |
|------|------|
| 确认误接受下界（RQ1） | 人群 A 确认的契约内缺陷数 / 基线接受帧；NO_DEFECT_FOUND 非真阴性，prevalence 仅带抽样权重报告 |
| 告警精度 | 各策略行: 确认告警 / 总告警（audited alarm precision） |
| 确认缺陷召回（RQ2） | 各策略行: 该行告警∩确认缺陷 / 全部确认缺陷（并集口径） |
| 成本 | GPU 秒/确认缺陷、time-to-first-counterexample、冷/热分离、Pareto 前沿 |
| 平反口径（RQ3） | false_equivalent 数 / 各 EMD 等级基数（人群 B 标签校验） |
| 不确定性 | task 聚类 bootstrap CI（10k）、配对 exact McNemar + Holm、INCONCLUSIVE 双极端敏感性 |

维度贡献用 leave-one-dimension-out（M7 §3.5），不用首杀计数单独说话。

### 3.5 工作量与最低可辩护设计

全量双标注不可行时（预注册后执行）：人群 A = 全告警 + 每层 N 条阴性；
人群 B = 分层金集（覆盖算子 × EMD 等级 × CSE 结果）；其余显式
INCONCLUSIVE 留在分母。标注前先跑 20–30 条 pilot 校准码本（协议既有流程）。

## 四、桥接接口

| 方向 | 接口 |
|------|------|
| M6/M8 → M9 | CounterexampleBundle → BlindBundle 导出；告警清单绑定 run digest |
| M7 → M9 | 审计队列生成请求（封存后）；接收 analysis_labels 计算确认口径 |
| M5 ← M9 | 人群 B 标签 → EMD 校准数据集（holdout 切分由 M5 §3.5 执行） |
| M4 ↔ M9 | 人群 C 复用标注/仲裁/agreement 工具与存储格式 |
| M9 → 论文 | statistics.json 为唯一推断性数据源；summary.json 仅描述性 |

## 五、与 V1 的差异摘要

| 维度 | V1 | V2 |
|------|----|----|
| 审计时序 | 检测阳性移出后审计（循环） | 封存 → 队列 → 双盲 → 锁定 → 口径 |
| 告警语义 | 222 直接称 defective | stress-flagged → 独立确认后才称 confirmed |
| 盲化 | 无 | 中立 ID + sealed mapping + 政策中立证据包 |
| 统计 | 点估计、独立性假设 | 聚类 bootstrap、配对检验、Holm、敏感性边界 |

## 六、实现注意

1. BlindBundle 导出是标注启动的唯一代码阻塞（工具链其余已就绪），
   优先实现并做 fresh-container 复放资格测试；
2. materialized inputs 用 safetensors 而非 pickle（安全 + 跨环境）；
   大张量做尺寸上限与按需下载约定；
3. 人群 B 标注者的"盲"包括不知道该探针属于历史 166/368 中哪一侧
   （协议已有要求，队列生成时校验字段泄漏）；
4. agreement 未达预注册阈值（如 kappa < 0.6）时的处置预先写明：
   码本修订 + 重标 pilot，而不是事后换指标。
